# 🔒 Write Guard для E2EE (End-to-End Encryption)

## Опис проблеми

**КРИТИЧНИЙ БАГ:** При вході користувача без пароля, автоматична синхронізація могла перезаписати зашифровані дані у Firestore порожніми локальними даними, що призводило до **безповоротної втрати даних**.

### Сценарій атаки:
1. ✅ У Firestore є зашифровані дані (`isEncrypted: true`)
2. 🔓 Користувач відкриває сайт (локальні дані порожні)
3. ⏱️ Поки користувач НЕ ввів пароль...
4. ❌ **Спрацьовує автосинхронізація → перезапис зашифрованих даних → ВТРАТА ДАНИХ**

---

## Рішення: Write Guard (Запобіжник запису)

### Реалізація

#### 1. Додано стан `isRemoteDataEncrypted` в `useFirestoreSync.ts`
```typescript
const [isRemoteDataEncrypted, setIsRemoteDataEncrypted] = useState(false);
```

**Коли встановлюється:**
- При виявленні зашифрованих даних: `{ isEncrypted: true, needsPassword: true }`
- Виводиться попередження: `🔒 Виявлено зашифровані дані в Firestore. Запис заблоковано до введення пароля.`

**Коли скидається:**
- Після успішного розшифрування даних в `processFirestoreData()`
- При явному вимкненні шифрування користувачем
- При завантаженні незашифрованих даних

#### 2. Додано блокування запису в `useSyncDebounce.ts`
```typescript
if (isRemoteDataEncrypted && !encryptionPassword) {
  console.warn('⛔ Блокування запису: Спроба перезаписати зашифровані дані без пароля!');
  setSyncStatus(getSyncStatusText('local'));
  return; // ЗУПИНКА — запис НЕ відбувається
}
```

#### 3. Передача стану через хуки
```
useFirestoreSync → useBudgetSync → useSyncDebounce
                 ↓
           isRemoteDataEncrypted
```

## Життєвий цикл захисту

### Сценарій 1: Вхід з зашифрованими даними
```
1. loadFromFirestore() → { isEncrypted: true, needsPassword: true }
2. setIsRemoteDataEncrypted(true) ← 🔒 БЛОКУВАННЯ АКТИВОВАНО
3. Показується модальне вікно для пароля
4. useSyncDebounce перевіряє: isRemoteDataEncrypted && !password → ⛔ ЗАПИС БЛОКОВАНО
5. Користувач вводить пароль
6. processFirestoreData() → setIsRemoteDataEncrypted(false) ← 🔓 БЛОКУВАННЯ ЗНЯТО
7. Синхронізація працює нормально
```

### Сценарій 2: Вхід без зашифрованих даних
```
1. loadFromFirestore() → звичайні дані
2. processFirestoreData() → setIsRemoteDataEncrypted(false)
3. Синхронізація працює нормально з самого початку
```

### Сценарій 3: Вимкнення шифрування
```
1. Користувач вимикає шифрування в налаштуваннях
2. handleDisableEncryption() → setEncryptionPassword(null)
3. saveToFirestore(password: null) → дані зберігаються незашифрованими
4. При наступному завантаженні: processFirestoreData() → setIsRemoteDataEncrypted(false)
```

## Тестові сценарії

### ✅ Тест 1: Захист від перезапису
**Передумова:** У Firestore є зашифровані дані  
**Крок 1:** Відкрити сайт без введення пароля  
**Очікуваний результат:** Попередження `⛔ Блокування запису` в консолі, статус "💾 Локально"  
**Перевірка:** Зашифровані дані в Firestore залишаються незмінними

### ✅ Тест 2: Розблокування після пароля
**Передумова:** isRemoteDataEncrypted = true  
**Крок 1:** Ввести правильний пароль  
**Крок 2:** Змінити локальні дані  
**Очікуваний результат:** Дані синхронізуються з Firestore, статус "☁️ Збережено"

### ✅ Тест 3: Вхід з незашифрованими даними
**Передумова:** У Firestore незашифровані дані  
**Крок 1:** Відкрити сайт  
**Очікуваний результат:** Дані завантажуються миттєво, синхронізація працює без блокувань
